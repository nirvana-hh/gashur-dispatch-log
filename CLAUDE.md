## Project

Gashur Dispatch Log: an internal app for Gashur Energy Limited's office and dispatch staff to register fuel-haulage trips, watch them on a dashboard, and get notified about each trip. Supabase is the backend (Postgres + email/password auth); setup steps are in README.md. Expo SDK 57, React Native 0.86, TypeScript (strict), Expo Router, React Compiler enabled (`app.json` → `experiments.reactCompiler`). Developed and demoed on a phone via Expo Go; npm is the package manager. Money is in US dollars (`Currency` in `calc.ts`), demo places are in Uganda, volumes in litres.

There is no test suite. Verification is `npx tsc --noEmit` plus `npx expo lint`; to confirm the app actually bundles, use `npx expo export --platform ios` (or `android`, `web`) with `--output-dir` pointed outside the repo.

The app is also tested in Chrome: `npx expo start --web` (or press `w` in a running `npx expo start`), served at http://localhost:8081. `app.json` sets `web.output` to `"single"` on purpose: with static rendering the seed data would be generated once on the server and again in the browser with different timestamps.

Typed routes are on (`experiments.typedRoutes`). Route types in `.expo/types/` are regenerated only while `npx expo start` runs, so after adding or renaming a screen, start the dev server once before `tsc`, or new `href`s fail to typecheck.

Do not run `npm run reset-project`: it is left over from the template and moves `src/` and `scripts/` into `example/`, wiping out the app.

## Architecture

- **[src/lib/store.ts](src/lib/store.ts) holds the data and every write.** It defines the types (`Trip`, `Truck`, `Driver`, `Client`, `AppNotification`), product and depot lists, and the action functions (`dispatchTrip`, `recordDelivery`, `recordInvoice`, `setPaid`, `markLossReviewed`, `saveTruck`/`saveDriver`/`saveClient`, `markAllRead`, ...). Trip actions also append trip notifications (dispatched, delivered, billed, paid, loss).
- **[src/lib/calc.ts](src/lib/calc.ts) holds everything derived**: per-trip figures (loss, variance against `LossTolerance`, shortage charge, revenue, margin, on-time), trip stage and billing status (overdue comes from the client's `creditDays`), "needs review", dashboard `summarize`, compliance reminders for licenses, service, insurance and inspection, and formatting and date-input helpers. None of this is stored; it's computed on render.
- **Two modes, chosen by env.** With `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` set (`.env.local`, see `.env.example`), the app requires sign-in and syncs with Supabase. Without them ([src/lib/supabase.ts](src/lib/supabase.ts) exports `supabase = null`) it is a local demo that seeds itself. Restart `expo start` after changing env.
- **The store is a local cache, and the UI reads only from it**, never from the network. It's one object persisted through [src/lib/persist.ts](src/lib/persist.ts) (`expo-sqlite/kv-store`'s sync API on native, localStorage on web) under `gashur:cache:v1` (Supabase mode, starts empty) or `gashur:v3` (local demo). Changing a stored type means bumping the key or migrating.
- **Sync ([src/lib/sync.ts](src/lib/sync.ts)).** Every store action passes `Op`s (`insert` = full row, `update` = changed columns only, deletes = `deleted_at`) to `update()`, which hands them to the sync engine through `onLocalChanges`. The engine keeps them in a persisted outbox and pushes them in order (inserts as upserts so retries are safe). Errors without a Postgres code are treated as offline: kept and retried with backoff. Refused changes are dropped and the row is re-fetched. Pulls read each table by `updated_at` since a stored cursor, minus a 5 s overlap, and merge through `applyRemote`, which skips records with queued local changes. Realtime events, app foreground and a 60 s timer trigger syncs. Row ↔ object mapping is in [src/lib/rows.ts](src/lib/rows.ts); add any new column there and in the migration.
- **Auth ([src/lib/session.ts](src/lib/session.ts)).** The session is read from device storage, so signed-in staff get their cached data offline. A different user signing in on the device, or signing out, wipes the cache and outbox. [src/app/_layout.tsx](src/app/_layout.tsx) gates every screen with `Stack.Protected` and shows `login` otherwise. Accounts are invite-only: managers create them in the app's Staff screen through the `staff-admin` edge function ([supabase/functions/](supabase/functions/), Deno, excluded from `tsc`/lint, holds the secret key), or in the Supabase dashboard. Removing access sets `profiles.active = false` and bans the account, so authors stay on their records. Forgot password emails a code (`resetPasswordForEmail` + `verifyOtp` type `recovery`), which needs the Reset password email template from `supabase/templates/`; `resetWithCode` holds the new session until the password is saved.
- **Roles and rules live in the database** ([supabase/migrations/](supabase/migrations/)). All staff (users with a `profiles` row, created by a trigger on sign-up) can read and write every table. Triggers stamp `created_by`/`updated_by`/`updated_at` server-side and refuse deletes or `loss_reviewed` changes from non-managers. Nothing is hard-deleted. The app mirrors the rules only to hide buttons (`useCanManage` in [src/hooks/use-session.ts](src/hooks/use-session.ts)). Notification read state is one timestamp per person (`profiles.notifications_read_at`).
- **Components read through [src/hooks/use-store.ts](src/hooks/use-store.ts)** (`useTrips`, `useTrucks`, `useDrivers`, `useClients`, `useNotifications`, `useStaff`, `useReadAt`, each `useSyncExternalStore` over one slice) and [src/hooks/use-session.ts](src/hooks/use-session.ts) (session, sync status, role, staff names). There is no context provider or state library. Updates replace only the slices that changed, so unchanged slices keep their array reference; selectors must return a stored reference, never a freshly built array, or `useSyncExternalStore` will loop.
- **Money rules** (all in `computeFigures`): loss = litres loaded − delivered; up to `LossTolerance` (0.5% of loaded) is allowed, and litres beyond it are charged back at `ProductInfo[product].pricePerLitre`. Revenue (the invoice amount) = delivered × the trip's `ratePerLitre` (copied from the client at dispatch) − that shortage charge; margin = revenue − the four delivery costs. Invoice amounts aren't stored, so editing a delivery after invoicing changes them.
- **Trip lifecycle**, in three form stages: dispatch (client, truck, driver, product, route, litres loaded, rate, due time) → delivery (litres delivered, arrival, costs, POD) → billing (invoice, payment). The stage is derived from which of `trip.delivery` / `trip.billing` / `billing.paidAt` are set.
- **Routes** (`src/app/`): the `(tabs)` group holds Dashboard (`index`), Trips (`trips`, with its filter in the `filter` URL param so the dashboard can link to it), Fleet and Clients. Outside the tabs: `trips/[id]` (detail), `trips/form` (the three-stage form, a modal, params `id` and `stage`), `notifications` (opened from the bell), `account` (opened from the initials button: sync status, change password, staff, demo data, sign out), `change-password`, `staff` and `edit/staff` (managers only), `edit/truck|driver|client` (pop-up add/edit forms), and, when signed out, `login` and `reset-password`. Header buttons are set in [src/app/(tabs)/_layout.tsx](src/app/(tabs)/_layout.tsx).
- **Styling** is plain `StyleSheet` with no UI kit. Shared pieces are in [src/components/ui.tsx](src/components/ui.tsx). Light/dark colors come from `useTheme()` (`Colors` in [src/constants/theme.ts](src/constants/theme.ts)), spacing from `Spacing`, and the brand orange from `Accent`. Stage, billing, urgency and product colors are defined in `calc.ts` and `store.ts`. Icons go through [src/components/icon.tsx](src/components/icon.tsx), which draws Material Symbols glyphs by code point on every platform so the phone matches the browser; add new icons there by code point (they're listed in `expo-symbols/build/android/symbols.json`). The icon font and the heading font (`HeadingFont`, Poppins, used for page and section titles) load in [src/app/_layout.tsx](src/app/_layout.tsx), which renders nothing until both are ready. List screens share [src/components/search-bar.tsx](src/components/search-bar.tsx) (`SearchBar`, `matchesQuery`).

## Lint gotcha

The React Compiler lint rules flag impure calls such as `Date.now()` made directly in a component body (`react-hooks/purity`). Put time-dependent checks in helpers in `src/lib/calc.ts` (e.g. `isWithinDays`, `dateUrgency`, `nowLocalInput`) and call those from components.

## Web gotcha

Don't wrap a `Pressable` whose `style` is a function (`({ pressed }) => ...`) in `<Link asChild>`: on web the style is dropped and the card renders unstyled. Navigate with `onPress={() => router.push(...)}` instead. React Native Web's `Alert` doesn't render buttons, so confirmations go through `confirmAction`/`showMessage` in `src/lib/confirm.ts`, which uses browser dialogs on web (`confirm.web.ts`).
